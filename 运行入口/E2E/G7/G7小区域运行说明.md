# G7小区域版运行说明

## 当前入口

在PyCharm使用`D:\Software\anaconda3\envs\PyTorch\python.exe`直接运行本目录的`G7小区域一键运行.py`，无需参数。

当前入口串联：小区域数据准备 → 两个seed的CH3/D8全模块适配 → 继承完整新权重训练统一候选生成器 → 新模型Top5/Top8覆盖比较 → 审计。不会启动旧G7或旧部分解冻v1，不自动进入局部F/S/E六轨，不读取test。

CH3/D8先从登记的原生权重warm-start，所有参数开放、归一化状态随训练更新，不是随机初始化。CH3保留原频带任务；D8使用BW_actual覆盖率≥0.2的19子带硬并集细图，保留原Heatmap＋offset任务。统一候选生成器继承这两套完整新权重，再沿原P2-B开放组训练；不会在候选推理中使用真实频带。后续三轨共享新候选。小区域独立硬级联可复用基础模型，但本入口尚不运行它的正式系统评价。

## 日志和恢复

- 控制台显示阶段、单行进度条、每轮耗时与最佳轮次；完整状态写入结果目录。
- 每seed依次训练CH3、D8和候选模型，各20轮、条件延长24轮，每2轮val_select选模，epoch 0也纳入选择；若保留epoch 0，应根据报告分析适配是否带来收益。基础模型按原生验证loss选模，同类两seed共同延长；候选按原联合定位指标选模。基准解码保留Top8，Top5仅作待复核候选。
- 输入4096/512/1024划分不变；本节点不进行val_compare模型比较，仅准备其输入。最终Top5复核使用512条val_select。
- 缓存512MiB有界懒加载，不保存网络高维特征。物理FP64/complex128，网络FP32。
- 正常中断后重跑同一入口，从上一个完整epoch恢复；未提交epoch重做。强制结束进程留下未关闭预算时需要先核对日志，不会自动清空用时。
- RAM85%、GPU14GiB、磁盘50GiB预留及累计12小时限制仍有效。入口先检查新版工程报告及时间/磁盘预测；原约7小时估算已作废。当前预测仅对应基础适配、候选训练和Top5复核，不包含后续局部六轨，预算不会按阶段自动重置。
- 只检查而不训练：给入口添加`--check`参数。

## 回读文件

固定结果目录：`outputs_e2e/unified/e2e_g7_compact/v2_full_adaptation/`。

运行结束后请回读：

1. `evaluation/运行摘要.md`
2. `evaluation/comparison_report.json`（含基础模型、候选模型和Top5报告；基础模型单独摘要另存`foundation_report.json`）
3. `evaluation/20260921_top5_report.json`和`20260922_top5_report.json`
4. `evaluation/final_audit_report.json`

报错时回读最后的控制台错误、`budget.json`、`progress.json`及对应`foundations/<seed>/ch3或d8/completed.json`或`training/<seed>/baseline/completed.json`。

Top5是否作为正式候选数，以新模型的覆盖报告决定；局部六轨的缓存生成、预算和一键编排将在该决定后接入，当前不伪装为已就绪。
